5. SUGGESTED EXAMINER WALKTHROUGH (approx. 12 minutes)
-----------------------------------------------------------------------------
 1. Open https://pulsetriage.vercel.app and sign in as patient@ug.edu.gh.

 2. SAFETY BEHAVIOUR. Click "Start Symptom Triage". Choose "Chest Pain /
    Palpitations", duration "Sudden (< 6 hours)", pain 9, and tick the red
    flag "Chest pain or pressure radiating to arm/jaw". Evaluate.
    EXPECTED: EMERGENCY at score 95, an emergency-services redirect, and NO
    booking option anywhere on the result. This is FR-2.6, the single
    safety-critical requirement.

 3. NORMAL PATH. Run a second triage: "Severe Headache / Dizziness /
    Numbness", "Sudden (< 6 hours)", pain 7, no red flags.
    EXPECTED: URGENT at score 71, Neurology recommended.

 4. REAL AVAILABILITY. Click through to booking. The time slots shown are
    generated from the consulting hours that clinician has actually saved -
    they are not a fixed list. Slots already taken are locked.
    Pay by Mobile Money with 0241234567.
    EXPECTED: reference PAY-SIM-nnnnnn, appointment becomes CONFIRMED.
    Entering 00000 instead demonstrates the declined path.

 5. URGENCY ORDERING. Sign out; sign in as dr.mensah@ug.edu.gh.
    EXPECTED: the queue is ordered by clinical urgency, not booking time.

 6. LIVE CONSULTATION. Open the same confirmed appointment as the patient in
    a second browser (or a phone) and as the doctor in the first. Both join
    the video room.
    EXPECTED: two-way audio and video, live chat, and - on the doctor's side
    only - the patient's intake record, a clinical notepad and an AI panel.

 7. CLINICAL AI. As the doctor, open "Clinical AI Suite" from the sidebar and
    press "Test live" on the status banner.
    EXPECTED: a live round-trip to Ollama Cloud naming the models consulted.
    If the banner is red, the deployment's OLLAMA_API_KEY is unset; the AI
    features will then report failure rather than inventing an answer.

 8. GOVERNANCE. Sign in as admin@ug.edu.gh and visit /admin (metrics and
    doctor verification), /admin/rules (rule list and simulator) and
    /admin/audit (append-only audit trail).

6. DISCLOSED LIMITATIONS
-----------------------------------------------------------------------------
The following are deliberate, documented limitations of a 48-hour
demonstrator, not undiscovered faults. Full analysis is in
Technical_Debt_Plan.docx.

  * The API layer does not enforce server-side authorisation (TD-01).
    PLEASE DO NOT ENTER REAL PERSONAL OR MEDICAL DATA INTO THE DEPLOYMENT.
  * Sessions are held unsigned in browser storage (TD-03).
  * Payments are fully simulated - no money moves (TD-11).
  * Notifications are in-application only; no e-mail or SMS is sent (TD-12).
  * Administrator rule edits are session-scoped and do not reach the
    patient-facing engine (TD-04).
  * Credentials committed early in the project remain in Git history pending
    rotation and a history purge (TD-02). The working tree is clean and is
    verified by "npm run scan:secrets".
  * There is no rate limiting on authentication or on the AI endpoints
    (TD-17). The AI routes incur real inference cost per call.
  * The clinical rule content is illustrative and has NOT been validated by
    a qualified clinical advisor.

7. DEFECTS CLOSED DURING THE EXAMINATION PERIOD
-----------------------------------------------------------------------------
  D-02  Hard-coded inference credentials removed from source; .env untracked;
        .gitignore corrected; a secret scanner and pre-commit hook added.
        Verify:  npm run scan:secrets

  D-03  "High fever with neck stiffness" and "Uncontrolled or heavy bleeding"
        were offered to patients as red flags but were bound to no EMERGENCY
        rule, so they added 10 points instead of triggering the safety
        short-circuit. RULE-007 and RULE-008 now bind them.
        Verify:  npm run test:unit   (TC-UNIT-03, TC-UNIT-13, TC-UNIT-14)

  D-06  Two patients could hold the same slot. A unique database constraint
        on (doctor_id, slot_key) now reserves each slot, with the key cleared
        on cancellation so the slot is released.
        Verify:  eight concurrent bookings of one slot produce exactly one
                 appointment; the rest receive HTTP 409.

  D-10  The consultation room showed a local camera preview only. It now
        carries two-way WebRTC media, signalled through the database.

  D-07  Patients can now reschedule and cancel their own confirmed
        appointments; rescheduling re-checks availability.

8. REPRODUCING THE BUILD LOCALLY
-----------------------------------------------------------------------------
    git clone https://github.com/NketiaAsubontengErnest/pulsetriage.git
    cd pulsetriage
    npm install
    cp .env.example .env        # set DATABASE_URL, optionally OLLAMA_API_KEY
    npm run db:push
    npm run db:seed
    npm run dev                 # http://localhost:3000

Verification commands:

    npm test            10 supporting-module tests
    npm run test:unit   34 rule-engine and scheduling unit tests
    npm run test:perf   NFR-1 latency harness (30,000 evaluations)
    npm run test:all    all of the above
    npx tsc --noEmit    static type check, zero errors expected
    npm run scan:secrets  secret scan over the full tree

    node tests/security-probe.mjs
        9 security probes against the live deployment. Five are EXPECTED to
        fail - those failures are the evidence for defects D-01 and D-05 in
        Testing_Report.docx.

Diagnostics:

        Reports whether the AI layer can reach Ollama Cloud, which models the
        account may use, and which are refused by the current plan.
